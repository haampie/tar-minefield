N51 linkname-bytes-after-nul

Bytes after the NUL that ends the target of a symlink.

Reject(draft) A strict parser must reject this archive.

The case¶

The archive has one symlink, l, whose linkname field contains safe, followed by a NUL, followed by ../x.

In POSIX, the linkname field is a string that ends with a NUL, unless it fills the field, so the target is safe. Copied as a whole, the field is safe as a C string, which ends at the first NUL, but safe\0../x in languages whose strings can contain a NUL: creating the link then fails, or a check of the target reads another string than the one that is used.

The bytes after the NUL have no meaning and no writer puts them there, so a strict parser rejects them rather than guess what they are for.

Decision point: where a link target ends.

Seen in: none of the scanned tarballs.
