The case¶

The archive has a GNU long name header of size 0, then a file whose header has GNU's magic and the name header-name.

A GNU long name replaces the name of the next member, and GNU's format does not say what an empty one means. If it applies, the pathname of the member is empty, and in POSIX an empty pathname does not resolve. This case is ambiguous because a reader can take the empty long name in one of three ways. A reader that ignores it extracts header-name. One that applies it gives the member an empty name, which is skipped, rejected or taken for .. One that takes the name of the long name header itself extracts the member as ././@LongLink. To a reader that does not know typeflag L, the member is header-name, after an empty file @LongLink.

Decision point: whether an empty GNU long name replaces the name in the header.

Seen in: none of the scanned tarballs.
