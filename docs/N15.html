The case¶

The archive has one file, a\nb, with a newline in its name.

The name is valid on Unix, as is any name with a control character, [\x01-\x1f\x7f]. POSIX encourages treating it as an error, but a reader that creates it has no other way to read it: the risk is in what is done with the name afterwards, where a newline makes it look like two names, a and b, in the output of ls piped to another command, in manifests and in scripts, and a carriage return or ESC makes a terminal show another name. A strict parser may reject it; the default policy tolerates it.
