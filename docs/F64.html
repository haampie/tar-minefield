F64 end-truncated-in-header

An archive that ends inside a header.

Reject(draft) A strict parser must reject this archive.

The case¶

The archive has a file a, then the first 300 bytes of the header of a file b, and ends there.

In POSIX, a header is a block of 512 bytes, so the archive is cut short. This case is ambiguous in practice because a reader can take the 300 bytes in one of three ways. A reader that takes a block that is not complete for the end of the archive extracts a, without an error. One that reads a header from the bytes that are there extracts a and an empty b. Other readers report an error.

Decision point: whether a header that is cut short ends the archive.

Seen in: none of the scanned tarballs.

The archive¶

Every block of 512 bytes, to scale, with its offset. Hover over a field for its bytes.
