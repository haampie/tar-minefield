N45 gnu-long-name-field-slash

A file with a GNU long name and typeflag NUL, whose name field ends in a slash.

Accept(draft) Every implementation must accept this archive, and extract the expected tree below.

The case¶

The archive has a GNU long name header whose data is 99 ps, followed by a slash, followed by file.py, followed by a NUL. After it is a regular file, of typeflag NUL, with GNU's magic. Its name field contains the first 100 bytes of the long name: the 99 ps, followed by the slash.

The long name replaces the name field, so the member is a regular file, file.py under the directory of 99 ps, which does not have a member of its own. The long name header is GNU tar's own format for long names. A name that ends in a slash was the old way to archive a directory. A reader that decides the kind by the name field, before the long name is applied, extracts a directory instead. A reader that does not apply the long name extracts a file of 99 ps, by the name field without its slash.
