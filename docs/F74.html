A pax size twice in one header: the first, or the last?

The case¶

The archive has a file a, whose pax header has the record size=0 and then the record size=512, and whose header has the size 0, then an empty file smuggled.

In POSIX, the last of conflicting records in one header takes precedence, so the size is 512, and the next block is the data of a. This case is ambiguous in practice because a reader that keeps the first record of a key reads 0, and the next block is the header of smuggled.

Decision point: which of two pax sizes in one header applies.

Seen in: not measured, as earlier versions of the scanner did not record which key a header has twice: the one scanned tarball that has a key twice, libmygpo-qt 1.2.0, does not have a pax size.
