F38-size-on-hardlink-without-pax: must reject

A size in the header of a hardlink, in an archive without pax headers: ustar or pax?

The archive has a file `a`, a hardlink `h` to `a` with size 512 in its header, and an empty file
`smuggled`, with no pax headers.

Hardlink sizes follow different rules in ustar and pax. In ustar, a hardlink's size must be
zero and the archive does not store data for it, making the block after
`h` the header of `smuggled`. In pax, a hardlink may carry data blocks and a non-zero
size, making that block `h`'s data. Although POSIX requires automatic format detection,
this archive matches both formats: pax uses the same physical layout and magic as
ustar, and extended headers are optional. Read as ustar, the extracted tree has
`a`, `h` and `smuggled`; read as pax, it has only `a` and `h`.

Decision point: whether a size in the header of a hardlink applies, in an archive without pax
headers.
Seen in: none of the scanned tarballs.
See also: F34, the same in an archive with a pax header, which marks it as pax.
