K04-name-empty-with-prefix: must reject

A regular file with an empty name and a prefix: `dir/`, or no name?

The archive has one member, whose header has typeflag `0`, a regular file, size 0, an empty name
field, and the prefix `dir`.

In POSIX, the pathname is the prefix, followed by `/`, followed by the name, which here is
empty, so the pathname is `dir/`. A member is extracted as a file of its own type, here
a regular file, but a name that ends in a slash resolves only to a directory, so
this is an error. A name that ends in a slash was the old way to archive a
directory, before the typeflag of a directory existed; it is in the rationale of
POSIX, but not in its rules. This case is ambiguous in practice because the member is either a
directory `dir`, by its trailing slash, an empty file `dir`, by its typeflag, or no file at all, if
the empty name field is taken for a missing name before the prefix is applied.

Decision point: whether a prefix makes a name of an empty name field, and whether the typeflag or
the trailing slash decides the kind.
Seen in: 7 tarballs have a regular file whose name ends in a slash, such as sendmail 8.18.2, all in
the name field; none has an empty name with a prefix.
See also: K01, a regular file whose name ends in a slash, and N17, an empty name.
