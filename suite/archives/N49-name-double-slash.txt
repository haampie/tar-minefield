N49-name-double-slash: tolerated: a strict parser may reject it; if it accepts it, it must extract its tree, and the default policy accepts it

A name with two slashes in a row, `a//b`.

The archive has one file, `a//b`.

In POSIX, files are created by pathname resolution, and in a pathname several slashes
in a row are the same as one, so the file is `a/b`. This case is ambiguous to a reader
that compares names as bytes, to which `a//b` and `a/b` are two names for one path, and to one that
takes what is between the two slashes for a component with an empty name, which it cannot create.
The default policy tolerates it, and normalizes the name to `a/b`, so that a second member of that
path is a duplicate.

Decision point: whether a name is normalized before it is compared with others.
Seen in: 2 of the scanned tarballs: shapemapper 2.1.5, and a binary distribution of GHC 9.0.2.
See also: N06, the name `./a`, and N50, a name with a `.` component.
