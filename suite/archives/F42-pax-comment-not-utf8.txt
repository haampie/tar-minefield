F42-pax-comment-not-utf8: must reject

A pax `comment` that is not UTF-8.

The archive has one file, `a`, whose pax header has one record, a `comment` of the two bytes
`\xff\xfe`, which are not UTF-8.

POSIX says that the value of every keyword it specifies, `comment` among them, is
UTF-8, and that every comment is ignored. So the archive is invalid, but a reader that
skips a comment never decodes it, and a reader that decodes every record before it looks at its
keyword finds the invalid one. This case is ambiguous because the archive is rejected, or has the
file `a`.

Decision point: whether a comment is decoded before it is ignored.
Seen in: none of the scanned tarballs.
See also: F43, the same comment in a global header.
