F11-magic-odd-version: must reject

The POSIX magic with a version that is neither `00` nor NULs.

The archive has one file, `a`, whose magic `ustar\0` is followed by the version `01`.

POSIX requires `00`. The default policy tolerates NULs instead, as some Java archivers
write them, but no other version. This case is ambiguous because a reader takes the header in one of
three ways: as ustar, ignoring the version; as not in a format that POSIX defines, and stops; or as
a v7 header, without the fields that ustar added, which here are empty, so that it gives the same
tree.

Decision point: which format the header is in.
Seen in: none of the scanned tarballs.
See also: F05, the POSIX magic with NULs for its version, which is tolerated.
