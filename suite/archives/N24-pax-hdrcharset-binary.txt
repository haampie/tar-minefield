N24-pax-hdrcharset-binary: must reject

A pax path that is not UTF-8, declared as bytes with `hdrcharset=BINARY`.

The archive has one file. Its pax header has `hdrcharset=BINARY` and the path `caf\xe9`, which is
`café` in Latin-1 and not UTF-8; its ustar header has the name `cafe`.

With `hdrcharset=BINARY`, the pax path is unencoded binary data, here the bytes
`caf\xe9`. But POSIX also has pax write a "diagnostic message" for a name that
cannot be translated "between the codeset in use for that extended header record and the character
set of the current locale", and by default bypass the file. This case is ambiguous because
the file is either created under those bytes, or bypassed, in a UTF-8 locale, to which they cannot
be translated.

Decision point: whether a pax path declared as bytes is created as it is.
Seen in: none of the scanned tarballs.
