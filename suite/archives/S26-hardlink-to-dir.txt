S26-hardlink-to-dir: must reject

A hardlink to a directory.

The archive has a directory `d` with a file `d/f`, then a hardlink `h` to `d`.

In POSIX, a hardlink is a link to a file of any type archived before it, which a
directory is. On most systems, a directory cannot be linked, and a link that cannot be
made is an error, or its data is restored from the original file. This case
is ambiguous in practice because a reader can take the link in one of five ways. A reader that
creates a member of the kind of its target extracts an empty directory `h`. One that copies the
target where it cannot link copies the directory with its contents, so that the tree has `h/f`. One
that makes a regular file of a link that it cannot create extracts an empty file `h`. One that skips
a link that it cannot make extracts `d` and `d/f` alone, without an error. Other readers report an
error.

Decision point: what a hardlink to a directory does.
Seen in: none of the scanned tarballs.
See also: S06, a hardlink to a symlink, and S03, a hardlink to a member that is not in the archive.
