F01-number-leading-space: tolerated: a strict parser may reject it; if it accepts it, it must extract its tree, and the default policy accepts it

Numeric fields padded with spaces rather than zeros, as old tars wrote them.

The archive has one file, `a`, whose mode, uid, gid, size and mtime fields are padded with spaces
rather than zeros, such as ` 7 ` for its size.

In POSIX, numeric fields are octal numbers filled with leading zeros.

Seen in: hundreds of tarballs, many from CPAN, which pad the checksum with spaces too.
See also: F32, a checksum padded with spaces, as those tarballs have it.

0x000000  header: regular file
          name     [  0,100)  "a" + 99 NUL
          mode     [100,108)  "   644 " + NUL
          uid      [108,116)  "     0 " + NUL
          gid      [116,124)  "     0 " + NUL
          size     [124,136)  "          7 "
          mtime    [136,148)  "          0 "
          chksum   [148,156)  "006345\0 "  3301: the unsigned sum of the header, this field as spaces
          typeflag [156,157)  "0"  regular file
          linkname [157,257)  100 NUL
          magic    [257,263)  "ustar" + NUL
          version  [263,265)  "00"
          uname    [265,297)  32 NUL
          gname    [297,329)  32 NUL
          devmajor [329,337)  "0000000" + NUL  0
          devminor [337,345)  "0000000" + NUL  0
          prefix   [345,500)  155 NUL
          pad      [500,512)  12 NUL
0x000200  data
          7 bytes, then 505 NUL to the end of the block
          "spaces\n"
0x000400  2 zero blocks: the end-of-archive marker
