F35-pax-size-on-hardlink: must reject

A pax `size` on a hard link, which takes the next header for its data.

The first member is a file `a`, the second a hard link `h` to `a`, whose pax extended header has
`size=512`. POSIX permits data on a hard link in pax, which this is, so the next block
is the data of `h`, but does not say what that data does: whether it replaces the contents of `a`,
or is ignored. A reader that applies the rule of ustar, that no data is stored for a hard
link, reads the block as the header of a file, `smuggled`. This case is ambiguous because the tree
has `a` as it is, `a` with that block as its contents, or `a` and `smuggled`. A reader may also make
`h` a file of the block, or give `smuggled` the size of `h`.

Decision point: whether a pax size applies to a hard link.
Seen in: none of the scanned tarballs.
See also: F15, a pax size on a directory, and F34, a size in the header of a hard link.
