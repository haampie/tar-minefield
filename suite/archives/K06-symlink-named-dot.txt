K06-symlink-named-dot: must reject

A symlink `.`: dropped, renamed, or an error?

The archive has a directory `d`, then a symlink `.` to `d`, then a file `f`.

The special filename dot refers to the directory that it is in, so in POSIX a
member `.` is the directory that the archive is extracted to. Creating a symlink there fails, as
the name exists, which is an error. This case is ambiguous in
practice because the symlink is dropped, as a name that normalizes to the root, and the tree is `d`
and `f`, or is created under another name, such as `_`, or the member is an error.

Decision point: whether a link may have the name `.`.
Seen in: not measured: 64 of the scanned tarballs have a member `.` or `./`, and the scans
did not record its kind.
See also: N05, a directory `./`.
