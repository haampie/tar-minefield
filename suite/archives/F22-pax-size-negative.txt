F22-pax-size-negative: must reject

A negative pax `size`, which a member cannot have.

The archive has a file `a`, whose pax header has `size=-512` and whose header has the size 0, then
an empty file `smuggled`.

In POSIX, a pax size is decimal digits, without a sign. Read leniently, this case is
ambiguous because the size is either what the header specifies, 0 (and the next block is the header
of `smuggled`), or the pax size read as an unsigned number, almost 2^64 (which runs past the end of
the archive). A reader may also extract nothing at all, without an error.

Decision point: whether a pax size may be negative, and what a negative one means.
Seen in: none of the scanned tarballs.
